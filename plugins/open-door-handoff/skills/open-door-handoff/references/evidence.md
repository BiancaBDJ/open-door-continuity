# Evidentiary labels and provenance

Use dated source references whenever possible: precise file/path, time, node ID, file digest (only if calculated), collaborator attribution, and source type.

Suggested claim type: `observation`, `interpretation`, `decision`, `correction`, `preference`, `unknown`.

Supported status: `observed`, `reviewed`, `contested`, `superseded`, `needs-review`, `missing`.

A checked source ID exists, but it does not automatically support the interpretation attached to it. Missing records remain missing. A later claim does not erase a previous claim, especially where stakes or preferences changed. Keep the user's authorship of their own preferences distinct from model-generated summaries.

Minimal evidence example (fictional):

> Claim `lantern-001`: The traveler preferred a violet lantern.
> Type: `preference`; Attribution: `traveler`; Evidence: `node-002` (fictional source); Status: `reviewed`.

Do not use this fictional example as evidence about a real person.
